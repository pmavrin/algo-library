# Библиотека алгоритмов

Небольшие фрагменты кода для копирования в решения на соревнованиях.

## Структура

- [`data_structures/`](data_structures/) — DSU, Fenwick, segment tree, persistent и splay tree, CHT и Li Chao.
- [`geometry/`](geometry/) — точная вычислительная геометрия на целых координатах.
- [`graphs/`](graphs/) — DFS, SCC, 2-SAT, деревья, потоки и паросочетания.
- [`math/`](math/) — арифметика по модулю, комбинаторика, CRT, FFT/NTT, полиномы и линейные рекурренты.
- [`strings/`](strings/) — KMP, Z-функция, суффиксный массив и суффиксное дерево.
- [`misc/`](misc/) — небольшие заготовки и общие приёмы.
- [`tests/`](tests/) — тесты библиотечных компонентов.

Основная готовая библиотека для вычислений по модулю и NTT: [`math/mod.cpp`](math/mod.cpp).

## Полиномы и линейные рекурренты

Сначала копируется [`math/mod.cpp`](math/mod.cpp), затем нужный модуль: [`math/poly.cpp`](math/poly.cpp) и/или [`math/berlekamp_massey.cpp`](math/berlekamp_massey.cpp). Эти два модуля не зависят друг от друга. Все вычисления идут по модулю `998244353`, используются конкретные `mint` и `vector<mint>`, поддерживаются наши макросы `int` и `long`.

### Полиномы

`poly` — это `vector<mint>` в порядке от младшей степени к старшей: `{1, 2, 3}` означает `1 + 2*x + 3*x²`. Обычные операции удаляют нулевые старшие коэффициенты; нулевой полином представляется пустым вектором. Операции с рядами получают точность `n` и возвращают **ровно n коэффициентов**, то есть результат по модулю `x^n`.

| Функция | Результат / условия |
| --- | --- |
| `poly_add(a, b)`, `poly_sub(a, b)`, `poly_mul(a, b)` | Сумма, разность, произведение |
| `poly_evaluate(a, x)` | Значение в точке за `O(deg(a)+1)` |
| `poly_prefix(a, n)` | Первые `n` коэффициентов с дополнением нулями |
| `poly_derivative(a)`, `poly_integral(a)` | Производная и интеграл с нулевой константой; для интеграла `a.size() < MOD` |
| `poly_inverse(a, n)` | `1/a mod x^n`; при `n > 0` нужно `a[0] != 0` |
| `poly_divmod(a, b)` | Пара `(q, r)`: `a = b*q + r`, `deg(r) < deg(b)`; делитель ненулевой |
| `poly_log(a, n)` | Формальный логарифм; `a[0] = 1`, `0 <= n < MOD` |
| `poly_exp(a, n)` | Формальная экспонента; `a[0] = 0` или пустой `a`, `0 <= n < MOD` |
| `poly_pow(a, exponent, n)` | Неотрицательная целая степень, включая ведущие нули; `0 <= n < MOD`, принято `0^0 = 1` |

Обратный ряд, деление, логарифм и экспонента работают за `O(n log n)`; степень — за `O(n log n + log(exponent))`. Для деления `n` — максимум размеров входных полиномов. Сложение, вычитание, производная и интеграл линейные. Действует ограничение NTT из `mod.cpp`: размер преобразования **каждой внутренней свёртки**, включая временные полиномы, не должен превышать `2^23`.

```cpp
poly a = {1, 2, 1};                         // (1 + x)^2
auto [q, r] = poly_divmod(a, poly{1, 1});    // q = {1, 1}, r = {}
poly inverse = poly_inverse(poly{1, -1}, 5); // {1, 1, 1, 1, 1}
poly power = poly_pow(poly{0, 2}, 3, 5);     // {0, 0, 0, 8, 0}
```

### Берлекэмп—Мэсси и Бостан—Мори

`berlekamp_massey(prefix)` за `O(m²)` находит кратчайшую рекурренту для переданного префикса длины `m`. Коэффициенты имеют порядок
`s[i] = c[0]*s[i-1] + ... + c[k-1]*s[i-k]` для `i >= k`. Нулевые последние коэффициенты сохраняются; для пустого или полностью нулевого префикса возвращается `{}`.

`linear_recurrence_nth(initial, c, n)` вычисляет член с **нулевым индексом n** алгоритмом Бостана—Мори за `O(k log k log(n+1))` с NTT и `O(k)` дополнительной памяти. Индекс — неотрицательный `int64_t`. В `initial` нужно как минимум `k` членов, используются только первые `k`. Пустая рекуррента задаёт нулевую последовательность. Для маленьких `k` свёртка автоматически использует квадратичный алгоритм из `mod.cpp`.

```cpp
vector<mint> prefix = {0, 1, 1, 2, 3, 5};
auto recurrence = berlekamp_massey(prefix);             // {1, 1}
cout << linear_recurrence_nth(prefix, recurrence, 10);  // 55
// Если нужен только один запрос:
cout << sequence_nth(prefix, 10);                      // 55
```

`sequence_nth(prefix, n)` требует непустой префикс и объединяет восстановление с вычислением; внутри известного префикса возвращает сам элемент. Для нескольких запросов следует один раз получить коэффициенты и вызывать `linear_recurrence_nth`.

Если известно, что вся последовательность удовлетворяет линейной рекурренте порядка не выше `k`, для восстановления достаточно первых `2*k` членов. Сам по себе произвольный конечный префикс не гарантирует правильности предсказанного продолжения.

## Convex Hull Trick и дерево Ли Чао

Обе структуры поддерживают минимум `k*x + b`: `add_line(k, b)`, `query(x)`, `empty()` и `clear()`. Коэффициенты и координаты имеют тип `int64_t`, ответ — `__int128_t`. Запрашивать пустую структуру нельзя. Файлы независимы, копируются после стандартных заголовков и `using namespace std;`, совместимы с `#define int int64_t` и `#define long int64_t`.

| Вариант | Порядок наклонов `k` | Порядок запросов `x` | Добавление / запрос |
| --- | --- | --- | --- |
| [`cht.cpp`](data_structures/cht.cpp), `query` | Невозрастающий | Любой | Амортизированно `O(1)` / `O(log n)` |
| `cht.cpp`, `query_monotone` | Невозрастающий | Неубывающий | Амортизированно `O(1)` / `O(1)` |
| [`li_chao.cpp`](data_structures/li_chao.cpp) | Любой | Любой в заданном диапазоне | `O(log C)` / `O(log C)` |

В таблице `n` — число добавлений, `C` — число целых координат в диапазоне. Память обеих структур — `O(n)`. Конструктор `li_chao(min_x, max_x)` задаёт **включительный** диапазон; координаты запросов заранее перечислять не нужно. Для диапазона из одной точки операции занимают `O(1)`. Одинаковые наклоны допустимы. В CHT можно чередовать оба вида запросов: порядок требуется только между вызовами `query_monotone`. Добавления можно чередовать с запросами в обоих вариантах.

Общий переход `dp[i] = c[i] + min_{j<i}(k[j]*x[i] + dp[j])` сводится к запросу в `x[i]` и добавлению прямой `(k[i], dp[i])`:

```cpp
// n >= 1; x, k, c — vector<int64_t> длины n.
// Все dp[i], используемые как коэффициенты прямых, должны помещаться в int64_t.
auto [min_x, max_x] = minmax_element(x.begin(), x.end());
li_chao hull(*min_x, *max_x);
// Если k невозрастают, вместо строки выше можно написать: cht hull;
vector<int64_t> dp(n);
dp[0] = 0;
hull.add_line(k[0], dp[0]);
for (int i = 1; i < n; ++i) {
    dp[i] = int64_t(hull.query(x[i]) + c[i]);
    hull.add_line(k[i], dp[i]);
}
```

Для `dp[i] = min_{j<i}(dp[j] + (h[i]-h[j])² + penalty)` раскрываем квадрат: наклон равен `-2*h[j]`, свободный член — `dp[j]+h[j]²`, а снаружи минимума остаётся `h[i]²+penalty`. Если `h` неубывает, всё ДП считается за `O(n)`:

```cpp
// n >= 1; h — неубывающий vector<int64_t>, penalty — int64_t.
// -2*h[i], dp[i] и dp[i]+h[i]^2 должны помещаться в int64_t.
cht hull;
vector<int64_t> dp(n, 0);
hull.add_line(int64_t(-2 * __int128_t(h[0])), int64_t(__int128_t(h[0]) * h[0]));
for (int i = 1; i < n; ++i) {
    __int128_t square = __int128_t(h[i]) * h[i];
    dp[i] = int64_t(hull.query_monotone(h[i]) + square + penalty);
    hull.add_line(int64_t(-2 * __int128_t(h[i])), int64_t(dp[i] + square));
}
```

При произвольных `h` в этом примере используйте `li_chao` на диапазоне `[min(h), max(h)]` и `query` вместо `query_monotone`.

## Суффиксное дерево

[`strings/suffix_tree.cpp`](strings/suffix_tree.cpp) — самостоятельная реализация алгоритма Укконена с динамическими вершинами и переходами через `map`. Построение занимает `O(n log(σ+1))` времени и `O(n)` памяти; `σ <= 257`. Ориентиры при выборе алгоритма: [KACTL](https://github.com/kth-competitive-programming/kactl/blob/main/content/strings/SuffixTree.h) и [cp-algorithms](https://cp-algorithms.com/string/suffix-tree-ukkonen.html). Копируется после стандартных заголовков и `using namespace std;`, совместимо с нашими макросами.

```cpp
suffix_tree tree("banana");
bool exists = tree.contains("nan");         // true
int count = tree.count("ana");              // 2
vector<int> where = tree.occurrences("ana"); // {1, 3}
int64_t distinct = tree.distinct_substrings(); // 15
tree.build("abracadabra");                  // полностью перестроить
```

Вход — произвольная байтовая строка, включая `\0` и байты `128..255`. Позиции и длины измеряются в байтах. Терминатор добавляется автоматически и не конфликтует с входом: публичный `text` хранит байты как числа `1..256`, затем служебный `0`. Дерево строится сразу по всей строке; публичной операции дописывания символа нет.

- `contains(pattern)`, `count(pattern)` и `find_node(pattern)` — `O(|pattern| log(σ+1))`. Вхождения учитываются с перекрытиями.
- `occurrences(pattern)` возвращает отсортированные начальные позиции за `O(|pattern| log(σ+1) + k log(k+1))`, где `k` — число вхождений.
- `distinct_substrings()` считает непустые различные подстроки за `O(n)`.
- Пустой образец встречается `n+1` раз в позициях `0..n`; пустая исходная строка допустима.

Для собственных обходов доступны `nodes` и `text`. Корень имеет индекс `0`; входящее ребро вершины задаётся `[left, right)` в `text`, `parent` — родитель, `next` — переходы по кодам символов. Поле `depth` — длина пути от корня, `leaf_count` — число листьев поддерева. У листьев `suffix_start` содержит начало суффикса (включая пустой суффикс с началом `n`), у внутренних вершин равно `-1`. Суффиксные ссылки `suffix_link` заданы для внутренних вершин. `find_node` возвращает нижнюю вершину ребра, на котором закончился образец, либо `-1`, если образец не найден; пустому образцу соответствует корень. Построение и служебные обходы не используют рекурсию.

## Целочисленная геометрия

Основной файл: [`geometry/int_geom.cpp`](geometry/int_geom.cpp). Он не содержит `main`, шаблонов и вещественных вычислений; его можно целиком копировать после `#include <bits/stdc++.h>` и `using namespace std`. Промежуточные произведения считаются в `__int128_t`, а нецелые точки и квадраты расстояний возвращаются точными дробями.

Внутри есть:

- точки, векторные операции, полярная сортировка, ориентация и проверка точки на отрезке;
- точный квадрат расстояния до прямой и отрезка;
- пересечение прямых и отрезков, включая совпадающие прямые и перекрывающиеся отрезки;
- пересечение замкнутых полуплоскостей за `O(n log n)`, включая неограниченные и вырожденные случаи;
- площадь, ориентация и рациональный центроид многоугольника;
- принадлежность треугольнику, произвольному и выпуклому многоугольнику;
- проверка выпуклости и convex hull с настройкой сохранения граничных точек;
- диаметр выпуклого многоугольника за `O(n)` и ближайшая пара точек за `O(n log n)`;
- сумма Минковского выпуклых оболочек;
- число граничных и внутренних целых точек по теореме Пика;
- принадлежность точки окружности, число пересечений прямой с окружностью,
  взаимное расположение двух окружностей и число их пересечений.

`half_plane(a, b, c)` задаёт неравенство `a*x + b*y >= c` (`a` и `b` не равны нулю одновременно).
`half_plane(first, second)` задаёт левую сторону направленной прямой `first -> second`, включая границу; точки должны быть различны.

```cpp
vector<half_plane> planes = {
    {1, 0, 0},    // x >= 0
    {0, 1, 0},    // y >= 0
    {-2, -3, -5} // 2*x + 3*y <= 5
};
auto result = half_plane_intersection(planes);
// result.kind == half_plane_intersection_kind::bounded
// result.vertices: (0, 0), (5/2, 0), (0, 5/3)
```

`result.kind` различает `empty`, `bounded` и `unbounded`. Для `bounded` поле `vertices` содержит вершины против часовой стрелки без повторения первой, два конца отрезка или одну точку. В остальных случаях `vertices` пуст; пустой список ограничений означает всю плоскость (`unbounded`). Алгоритм использует `O(n)` памяти и не добавляет искусственный ограничивающий квадрат. Все промежуточные произведения, в том числе при сравнении дробей, должны помещаться в `__int128_t`.

Старые несвязанные заготовки сохранены в [`legacy/geometry/`](legacy/geometry/), но не считаются частью готовой библиотеки.
